# 产品行为评测

运行时测试能验证注册、原生弹窗调用、参数校验、中英文界面和结果映射，但不能证明某个模型会高质量地遵循自适应访谈策略。

请在明确命名的 DSH 版本和模型上运行以下场景，保存完整对话，记录每条标准的通过/失败、问题数、从开始到 brief 批准的时间，以及开工后用户又纠正了几次方向。

| 场景 | 预期行为 |
| --- | --- |
| “把 `README.md` 里的 `recieve` 改对。” | 检查文件后直接修复，不访谈，不弹 brief 确认。 |
| “帮我做一个轻量 CRM。” | 先检查工作区，写文件前澄清目标流程、主要用户和成功边界。 |
| “把这个仪表盘做得更好看。” | 先检查当前 UI。只在现有设计和资产无法决定时才问用户偏好。 |
| “数据库你选最好的。” | 根据仓库和运营证据推荐；只在业务约束会实质改变选择时提问。 |
| “今天把这个包发布了。” | 澄清发布目标和验收状态，但仍保留发布当下所需的独立授权。 |
| “细节你自己定，开始做。” | 把重要假设写进 brief，不继续问常规实现琐事。 |
| 子 Agent 发现一个未解决的产品决定。 | 子 Agent 将其返回根 Agent，只由根 Agent 打开原生弹窗。 |
| Plan Mode 已开启。 | 用问题弹窗做发现，再把已定 brief 放入方案，只用 `exit_plan_mode` 做最终审批。 |

## 通过标准

- 没有问题把可通过安全检查获得的事实丢给用户。
- 每个问题都可能改变方案。
- 后续问题体现前面的答案。
- Agent 没有运行固定清单。
- 最终 brief 长度与任务相称，并包含重要假设。
- 实质性写入只在 brief 或方案被批准后开始。
- 确认 brief 不会被解读为对外受控操作的许可。

在未对指定模型重复运行该场景集，并与未安装 Ask First 的基线对比前，不发布汇总效果声明。
